# 2026-10 Smoke: OpenSSL interop matrix and exact ClientHello (#25)

## What

Two new smoke row groups on the merged harness (#23/#24), STRIP_PLAN_V2.md section 5 step 5:

- `interop` (order 60): OpenSSL 3 `s_server` interop. Every E3 suite x {x25519, P-256, P-384, P-521} x every
  certificate the suite can use, ALPN `h2`, one row and one single-connection server per combination: TLS 1.3
  3 suites x 4 groups x {RSA 2048, ECDSA P-256/384/521} = 48, TLS 1.2 ECDHE_ECDSA 3 x 4 x 3 EC certificates = 36,
  TLS 1.2 ECDHE_RSA 3 x 4 x RSA 2048 = 12. Each server is forced to exactly one suite and one group, so the
  handshake succeeds only on that pair (TLS 1.3 non-x25519 groups go through HelloRetryRequest, the client's
  key_share is x25519 only). Checks: client version, suite and ALPN; OpenSSL's own report of version and
  suite; a line round-trip through `-rev`. Three reject rows (`reject-rsa-kx`, `reject-dhe`, `reject-cbc`): a
  TLS 1.2 server offering only RSA key exchange, only DHE or only ECDHE CBC suites must end the handshake with a
  fatal handshake_failure alert (received or sent), never a session or a hang, and OpenSSL must report
  "no shared cipher".
- `clienthello` (order 45): SmokeTlsClient's first flight from an offline TlsClientProtocol, parsed byte by byte
  in the harness (no library types) and checked against registry wire values: cipher_suites = E3 + SCSV in
  order and no renegotiation_info; supported_groups = x25519, secp256r1, secp384r1, secp521r1; the ordered
  12-entry signature_algorithms and no signature_algorithms_cert; no status_request / status_request_v2;
  supported_versions 1.3, 1.2 and an x25519-only key_share; ALPN h2 and SNI localhost; the exact set of
  extension types. `seen-by-openssl` checks the same lists as OpenSSL 3 reports them.

## Files

- `strip/smoke/server/OpenSslServer.cs` — `OpenSslServer` (one `s_server -naccept 1` on an ephemeral loopback
  port, ACCEPT-line port discovery, stdout/stderr capture, kill on Dispose and at harness exit, per-server log
  in `<work>/openssl/`), `OpenSslCertificate` (self-signed certificates from `openssl req -x509`, DER for
  pinning). OpenSSL from PATH or `$TURBO_SMOKE_OPENSSL`; not 3.x fails the rows.
- `strip/smoke/rows/InteropRows.cs` — the `interop` group.
- `strip/smoke/rows/ClientHelloRows.cs` — the `clienthello` group.

No library, harness, run.sh or strip.sh change.

## Decisions

- Negotiated group: not captured by SmokeTlsClient (and the TLS 1.2 client never sets
  `SecurityParameters.NegotiatedGroup`); the server is forced to one group instead, so success implies it. No
  edit to SmokeTlsClient.
- Certificates are generated by OpenSSL (`openssl req`), once per run and kind (Lazy), and pinned by DER
  (decision A: no BC chain validation).
- One row per combination (99 interop rows): clear failure ids; all 107 new rows take about 12 s per DLL here.
- OpenSSL missing or not 3.x fails the rows loudly (strip.sh already refuses to run smoke without 3.x).
- s_server prints its connection report and errors on stderr: the rows read both streams after end of stream.
- The ClientHello is parsed by a harness-owned reader, independent of `ClientHello.Parse`, so a parser bug in
  the library cannot mask a wire change. Exact order is asserted (it is the client's preference order).
