# 2026-10 — E14: GCM always BasicGcmMultiplier; AesLightEngine without AES-NI (#21)

## What

Edge cut E14 (STRIP_PLAN_V2.md §2 G, §3 E14), on top of E1:

- `GcmBlockCipher.CreateGcmMultiplier` always returns `new BasicGcmMultiplier()` (constant-time GHASH). The
  `Tables4kGcmMultiplier` fallback (key-dependent table lookups) is no longer used when PCLMULQDQ is absent.
- `BcTlsCrypto.CreateAesEngine` returns `AesUtilities.CreateEngine()` (AES-NI `AesEngine_X86`) only when
  `AesUtilities.IsHardwareAccelerated`, else `new AesLightEngine()` (256-byte S-box, 4 cache lines) instead of the
  table-heavy `AesEngine`.

## Files

- `crypto/src/crypto/modes/GCMBlockCipher.cs` — `CreateGcmMultiplier` body, one `// turbo-strip: E14` hunk.
- `crypto/src/tls/crypto/impl/bc/BcTlsCrypto.cs` — `CreateAesEngine` body, one `// turbo-strip: E14` hunk.
- `crypto/test/src/turbo/GcmAesE14Test.cs` — new plain-NUnit fixture (`Org.BouncyCastle.Turbo.Tests.GcmAesE14Test`),
  the E14 regression check until the smoke harness (#23/#24) exists: `CreateGcmMultiplier` is Basic; a default
  (one-argument) `GcmBlockCipher` holds a Basic multiplier; `BcTlsCrypto.CreateAesEngine` is `AesLightEngine` without
  hardware AES; McGrew-Viega GCM test cases 1-4 and 16 (copied from `GCMTest.cs`) through `AesLightEngine` + default
  multiplier and through the TLS engine + default multiplier, encrypt, decrypt and tampered-tag rejection.

## Decisions

- `[Obsolete]`: `new BasicGcmMultiplier()` sits inside `GCMBlockCipher.cs`, which already has a file-wide
  `#pragma warning disable CS0618`; `BcTlsCrypto.cs` references no obsolete member. No new pragma, no other caller
  touched (`GcmSivBlockCipher` inherits the Basic multiplier through `CreateGcmMultiplier`; GCM-SIV is not on the TLS
  surface). The test file disables CS0618 locally. Revisit at the BC v3 bump (plan §2 G).
- `IsFourWaySupported` (net6.0 + PCLMULQDQ/SSSE3) still routes GCM to the 4-way carry-less-multiply path. Not a
  defect: hardware CLMUL is constant-time, the plan does not cut it, and Unity defines are not
  `NETCOREAPP3_0_OR_GREATER`, so it is outside the shipped define sets.
- Under Unity define sets `AesUtilities.IsHardwareAccelerated` is always false, so the shipped client always runs
  `AesLightEngine` (plan §2 G: leak reduced, not removed; ChaCha20 is offered first).

## Deferred / closure notes

- `Tables4kGcmMultiplier` and `BasicGcmMultiplier.IsHardwareAccelerated` lose their only reference in
  `GCMBlockCipher.cs`; `AesEngine` stays reachable through `AesUtilities.CreateEngine`'s non-accelerated branch.
  Whether they leave the closure is the closure tool's call (#6/#7), not this cut.
- Smoke rows for this check belong to the primitive-KAT smoke issue (#24) once the harness exists.
