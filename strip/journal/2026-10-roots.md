## Decisions

- **ROOTS_SHA = the commit copied from** (`git rev-parse <rev>^{commit}`, full 40 hex), HEAD by
  default — what `--refresh-roots` writes; not the last commit touching the files.
- **Copies come from the commit, not the working tree** (`git show <sha>:<path>`), so the copies
  always match `ROOTS_SHA` even if the turboHTTP checkout is dirty; no clean-tree check needed.
  `--rev` pins another commit (e.g. the #33 merge).
- **Only the three consumer files are refreshed.** `RootStubs.cs` and `roots-extra.cs` are
  maintained here (new contract entries come from turboHTTP #33 via #141); `*.meta`, `Lib/`,
  the asmdef and any other file are never copied.
- **Round trip enforced:** a source with an unprefixed `Org.BouncyCastle` token is an error, and every
  copy must satisfy `rewrite.rewrite_bytes(copy) == source`, so strip.sh's forward rewrite (§5
  step 3c) restores the consumer files exactly. All files are read and checked before any write; a
  file whose bytes are current is not rewritten (idempotent).
- **`--turbohttp` must be the checkout's top level** and a git work tree, and `--rev` may not start
  with `-` (no option injection into git); anything else is an error.
- **Stub fidelity:** `TlsResult` mirrors turboHTTP's members and defaults, so the smoke suite can
  run the consumer path on the stubs later; the plan only requires the 5-argument constructor.
- `strip.sh` (#10) wires `--refresh-roots --turbohttp <path>` to this script; `closure.py` already
  takes `--roots strip/roots` (roots-extra.cs included, unrewritten).
