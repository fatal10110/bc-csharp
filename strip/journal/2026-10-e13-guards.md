# 2026-10 — E13: `#if` guard fixes for the provisional define sets (#20, part)

## What

Edge cut E13 (STRIP_PLAN_V2.md §3 E13): the smallest `#if` guard edits for every guard mismatch that
`strip/strip.sh --report` exposes under the PROVISIONAL `strip/unity-defines.txt` sets `[min]`, `[partial]` and
`[sdk]`. Each fix widens an existing older-symbol guard by `|| NETSTANDARD2_1_OR_GREATER`, so the `using` (or helper
overload) is present wherever the Span/ValueTask code that needs it (guarded
`NETCOREAPP2_1_OR_GREATER || NETSTANDARD2_1_OR_GREATER`) compiles. One `// turbo-strip: E13` line per hunk.

`strip/unity-defines.txt` is still provisional (#29 open), so #20 stays open for #30 (real Unity sets).

## Decisions

- **Widen the using guard, never drop the use-site attribute.** One-line edit per file, the same shape everywhere,
  and the `[MethodImpl]` hints stay on the Span paths. Upstream rebases touch only these header lines.
- **Library TFMs compile to the same code.** The added term is redundant on every TFM the library builds:
  net6.0 has `NETCOREAPP1_0/3_0_OR_GREATER`, netstandard2.0 has `NETSTANDARD1_0_OR_GREATER`, and net461 lacks
  `NETSTANDARD2_1_OR_GREATER`, so each guard evaluates as before. No `#else` path changes; constant-time code is
  untouched (usings and one helper overload only).
- **X448Field.cs is edited although denied** (`**/*x448*`). Under [partial] the fixpoint still compiles it (it is
  reached before the deny step drops it). Its declaration-level CS0246 on `[MethodImpl]` stops the compiler before
  method bodies, so the fixpoint stalls and the sweep reports "sweep error no denied file explains" for about 1300
  body errors. The one-line guard fix lets the fixpoint finish. The file still leaves the kept list through the deny list.
- **Only report-driven files.** `MacSink.cs`, `CipherStream.cs`, `DigestStream.cs`, `MacStream.cs`, `SignerStream.cs`,
  `PushbackStream.cs` (named in #20's 17-file list) are not in any provisional closure, or compile already. They are
  left untouched until a report (the real #29 sets, #30) exposes them.
- **Older-triple-guarded overrides that still drop out under [partial]** (`CopyToAsync` in TlsStream, FilterStream,
  BaseInputStream, BaseOutputStream; `WriteAsync(byte[],...)` in the sinks) compile fine either way and fall back to
  the `System.IO.Stream` base implementations, as they already do under [min]. They are not guard mismatches, so they
  are not widened.

## Closure effect (`--report`, per set)

Before E13, declaration-level errors stopped the [partial] fixpoint at 168 files (8 unresolved), and [sdk] stopped
at the Poly1305 `[MethodImpl]` errors. Each round of fixes exposed the next file. The iterations under [partial] were:
Base/FilterStream, then Pack, then Streams/TlsStream/BaseOutputStream, then ChaCha7539Engine/Poly1305, then
DigestSink/SignerSink, then X448Field (denied), and finally Streams `WriteAsyncCompletion`.

After E13 all three sets reach the same fixpoint state:

- kept: [min] 712, [partial] 712, [sdk] 713, union (default run) 714 files.
  - [partial]/[sdk] add `util/Spans.cs` and drop `crypto/prng/CryptoApiRandomGenerator.cs`.
  - [sdk] also adds `util/collections/ReadOnlySet.cs`.
- 0 unresolved errors, sweep complete, 65 identical deny hits per set.
- 10 identical compile errors in builds 3a/3c for every set: `DigestUtilities.cs:403-408`, `MacUtilities.cs:298`,
  `ECKeyPairGenerator.cs:38,46` and `X509ExtensionUtil.cs:17`. These are the deny-forced helper cuts E9–E12 (#19),
  not guard mismatches.

  and the build errors matched [min]. A final `strip/strip.sh --report` (all sets) shows the same.

- `./tools/ci/check.sh` (see the PR's Local gates section).
- No NUnit fixture: the edit is compile-time only, the compiled code of the library TFMs is unchanged, and the 3a/3b
  per-set builds are the regression check that fails on the old code. Once #30 switches to enforce mode, it fails the
  gate on any regression.
